# 40 FP8 P2 兑现与 fp8 时代的重叠上限账

> tp_run_20260712_120250。用户裁定:fp8 计算收益大家都封顶(~1.3×),
> 差异化转向**通算融合的可重叠优化上限**。

## 1. P2 实测

| 档位 | serial fp8 | tktp fp8 | 比率 | 我方 bf16 对照 |
|---|---:|---:|---:|---:|
| T=512 | 2074 | **~1920** | 1.08× | 2116(−196) |
| T=1024 | 4025 | **3239** | **1.24×** | 3781(−542) |

- bench 轮 t512 med 3564 又是环境干扰(正确性轮稳定 1921/1928,取稳定值);
- **AG 减半的结构优势兑现**:T=1024 拉开到 1.24×(serial 的 AG 传 bf16
  没法减);
- 数值:rel_err 3.76e-2(serial fp8 1.67e-2 也 FAIL 元素级容差),0.9%
  元素超容差,max_abs 0.081。我们多出的部分来自"反量化→交织→重量化"的
  二次量化 + 混合 gate/up 块的保守 scale。量级合理;改进项(P4):从
  原始 bf16 直接做交织后量化(需 data 侧配合)。TP fp8 容差校准:与
  serial 同病,建议 fp8 元素级容差放到 (5e-2, 5e-2) 或按 rel_err<5e-2
  判——待与用户确认口径。

## 2. fp8 时代的重叠上限账(T=512)

```
当前 1920 ≈ sched 268 + quant/屏障 ~55 + L0_fused ~890 + L1(bf16) 691
          + final_red 20 − 已重叠 ~65
上限 ≈ GEMM(L0 750 + L1 380)×让渡因子(~1.12 @cs≈12) + sched 残 ~200 + 杂 45
     ≈ **~1510 → 1.37× vs serial fp8**
```

四个抓手(性价比序):

| # | 项 | 预估 | 状态 |
|---|---|---:|---|
| A | **fp8 comm_sms 重扫**:AG 字节减半 → 拉取所需 SM 减半,拐点 24 应左移到 ~12-16;每省 8 SM ≈ GEMM −60µs | −40~80 | **本轮落地 05f sweep {8,12,16,24}** |
| B | **L1 fp8(P3)**:w2 fp8 + act 量化(v0 独立 kernel ~35µs,v1 融 GLU epilogue) | −100~130 | 下轮 |
| C | **sched 双流重叠 + 瘦身**:routing gather/builder 与 quant/屏障并行;argsort 合并 | −60~100 | 排 B 后 |
| D | final_red 融进 L1 排空尾 | −20 | 排后 |

## 3. 本轮落地

- 05f:fp8 comm_sms sweep {8,12,16,24};
- 08f + time_tp_stages fp8 化(tok_copy 含量化、L0 走 tpdisp8、
  L0_gemm_alone 用 gg8 参考)——fp8 归因不再盲调;
- 下轮命令:

```bash
STEPS='^00_|^01_|^05f_|^08f_' bash tools/run_tp_all.sh   # ~3 分钟
```

看点:fp8 拐点位置 + 08f 的 L0 暴露/让渡分解 → 决定 A 的定档与 B 的预期。
