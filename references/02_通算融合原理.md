# 通算融合原理

## 1. 核心问题：shared tensor 依赖分析

通算融合的对象是连接通信与计算的 **shared tensor**——它是生产者算子的输出缓冲，也是消费者算子的输入缓冲。关键观察：

- shared tensor 可以被**分解**（沿某个维度切片），当且仅当消费者在该维度上不需要跨片做规约。
- 分解后，生产者和消费者可以按片交错执行——一片数据就位即可启动对应片的消费者，不必等全部数据。

### 1.1 两个阶段的 shared tensor

| 阶段 | shared tensor | 生产者→消费者 | 全局大小 |
|---|---|---|---|
| layer0 | AllGather 后的全量 token 缓冲 | 通信(AG) → 计算(GEMM) | (M, K) |
| layer1 | Grouped GEMM 输出（expert 排序行） | 计算(GEMM) → 通信(RS) | (M, N) |

### 1.2 分解维度的选取原则

**沿"消费者不需要跨该维做规约"的维度分解 shared tensor**：

- **layer0**：消费者是 GEMM，token 行（M 维）彼此独立 → **沿 M 切**。再把 token 按**来源 rank**排序，让每个 M-tile 只依赖 1~2 个源 rank，本地数据对应的 tile 最先算。
- **layer1**：消费者是 topk 规约，M 维上同一 token 的 topk 行**强依赖** → 不能沿 M 切；输出各列独立 → **沿 N 切**。GEMM 的问题空间按 N 切成 n_split 片，每片跨**所有** expert；一片算完，这片列上所有 token 即可立刻规约+通信，与后续片的计算重叠。

记忆口诀：**layer0 沿 M 切（按源 rank 排），layer1 沿 N 切（按列分片）**。

## 2. 两种融合形态

| 形态 | 做法 | 适用 | 使用场景 |
|---|---|---|---|
| **垂直融合**（vertical） | 通信逻辑塞进计算 kernel 的 prologue/epilogue，所有 threadblock 同构 | 依赖方向是 **通信→计算**（等数据），或规则的 epilogue 直写 | **layer0**：AllGather 的"等灯"融进 GEMM prologue（通信本体在另一条 stream 上由 DMA 完成，kernel 里只有 wait） |
| **水平融合**（horizontal） | 计算 kernel 与通信 kernel **并列**：少量 CTA 专职通信，其余专职计算，SM 级隔离 | 依赖方向是 **计算→通信**，且通信侧访存 pattern 复杂（随机行聚合 + 规约 + 跨卡写） | **layer1**：GEMM（让出若干 SM）+ 高优先级 stream 上的 reducer kernel（gather + topk 加权求和 + ring ReduceScatter） |

### 2.1 为什么 layer1 不用垂直融合

combine 需要把**同一 token 的 topk 行**（散落在不同 expert 段、可能由不同 tile 产出）聚在一起规约，GEMM epilogue 的规则 tile 迭代做不了这种跨 tile 的随机聚合；而且细粒度远端 I/O 混进计算块会拖垮流水。把它关进专门的通信 CTA（数量可调，即 n_c），计算块保持原生 GEMM。

### 2.2 自适应负载分配

通信 CTA 数（n_c）与计算 CTA 数（n_p）的最优划分点随 M、TP/EP、硬件变化。工程做法**不是**运行时改 block 数，而是：预编译/预设几组划分参数 → 离线 profile 各种输入尺寸 → 存成 metadata 表 → 运行时按输入查表选择。PCIe 上通信更慢，**n_c 需要更大**、通信粒度可能需要更粗，必须在目标硬件上重新 profile。

## 3. Layer0：AGScatter 的完整机制

### 3.1 目标

`output = scatter(all_gather(inputs_shard)[gather_index]) @ weights^T`，按 expert 分组。

### 3.2 缓冲布局

每 rank 两块**对称缓冲**（所有 rank 可见）：

- `input_buffer[r]`：`[max_ntokens, K]`。rank r 的分片固定放在自己 buffer 的第 r 段；AllGather 把其余 rank 的段填进来。
- `barrier[r]`：`int32[world_size]` 的"红绿灯"数组。`barrier[r][s] == 1` 表示"第 s 段（即 rank s 的分片）已在 rank r 的 input_buffer 里就位"。

**GEMM 只读本地** `input_buffer[rank]` 和本地 `barrier[rank]`——跨卡数据搬运与点灯全部由 AG 生产者完成。这个"消费侧只碰本地"的结构是 PCIe 迁移能保住的关键。

### 3.3 AllGather 生产者（独立 copy stream）

对 bf16/fp16 默认走 **DMA 路径**：host 在 `cp_stream` 上按环形调度发一串 `cudaMemcpyAsync`（P2P），每段拷贝之后按流序用 `cuStreamWriteValue32` 把目标 rank 的 `barrier[dst][seg]` 置 1（流序保证数据先落、灯后亮）。

Ring1D push 模式伪代码：

```
for step in 0..world_size-1:
    seg = (rank + step) % world_size          # 本步转发哪个段
    if step > 0: stream_wait_value(barrier[rank][seg] == 1)   # 等上游送到本地
    memcpy_async(input_buffer[next_rank] 的 seg 段 ← input_buffer[rank] 的 seg 段)
    stream_write_value(barrier[next_rank][seg] = 1)           # 点亮下游的灯
```

本 rank 分片的 self-copy 与 barrier 清零在 forward 开始时完成，并 record 一个 event；GEMM stream 先等这个 event（保证前置条件），**但不等 AG 完成**——重叠即由此而来。

### 3.4 路由元数据的加工（device 侧，与 AG 并行）

在主 stream 上跑三个小 kernel（AG 在 cp_stream 上同时进行）：

1. **求逆映射**：由 `scatter_index` 生成 `gather_index[j] = 该排序行的源 token 行号`，并算出本 EP rank 的行数 `M_this_ep`。
2. **按 (expert, 源rank) 稳定排序**：在每个 expert 的行段内部，把行按**源 rank** 分组排序，产出：
   - `sorted_gather_index / sorted_scatter_index`：排序后的读/写索引；
   - `sorted_splits_cumsum`：**每个 expert 内 per-rank 的含入累积行数**，布局 `[expert][rank]`（rank 连续）。这张表是 GEMM tile 判断"我依赖哪几个 rank"的字典。
3. **scatter 目标重基**：把 scatter 目标从全局排序行号改成 per-expert 局部行号。

> 排序的意义：一个 M-tile（BLK_M 行）在排序后只覆盖**少数几个连续源 rank** 的行 → 只需等这几个 rank 的灯 → 本地/早到数据对应的 tile 立即可算。

### 3.5 tile 重排：按"到达阶段"发射

把 ring 的到达顺序编码进 tile 顺序：定义 `stage`，`segment(stage) = (stage + rank) % world_size`——stage 0 是本地段（永远就绪），stage 越大数据越晚到。对每个 expert：

- 用 `sorted_splits_cumsum` 把每个 stage 的行区间换算成 M-tile 区间；
- **跨 stage 边界的 tile 归属它覆盖的最晚 stage**（保证发射时其全部依赖都已在等待集合内，且每 tile 恰好发射一次）；
- 按 stage 从小到大展开成 `ProblemInfo{problem_idx, tile_idx}` 线性表，以 round-robin 方式交错分配给各 threadblock。

效果：所有 block 首先算 stage 0（本地数据）的 tile，此时 AG 正在搬 stage 1、2... 的数据；等到 block 推进到后面 stage 的 tile 时，数据大概率已就位，自旋时间趋近于零。

### 3.6 融合 GEMM kernel 的到达等待

标准 grouped GEMM（非持久、`cp.async` 多级流水 + `mma.sync`、GatherA/ScatterD 迭代器），唯一的插入点是**每个 tile 开始前的到达等待**：

```
kernel ag_scatter_grouped_gemm(params):
  visitor = ProblemVisitor(params.problem_info, *params.tile_count, blockIdx.x)
  while visitor.next_tile():
    (problem_idx, tile_m, tile_n) = visitor.current()
    m_lo = tile_m*BLK_M;  m_hi = min(m_lo+BLK_M, M_i) - 1

    # ---- 到达等待：只等本 tile 覆盖的源 rank ----
    cum = params.split_cumsum + world_size * (problem_idx % E_local)  # 该 expert 的 per-rank 累积表
    lane = threadIdx.x % 32
    # warp 内 lane r 代表 rank r；ballot 得到 m_lo/m_hi 落进哪个 rank 段
    seg_lo = ffs(ballot(lane < ws && m_lo < cum[lane])) - 1
    seg_hi = ffs(ballot(lane < ws && m_hi < cum[lane])) - 1
    if seg_lo <= lane <= seg_hi:
        while atomic_load_acquire(barrier_local[lane]) != 1: pause   # 自旋红绿灯（本地 flag）
    __syncthreads()

    # ---- 之后与普通 grouped GEMM 完全相同 ----
    A_iter = gather_iterator(input_buffer, gather_A[problem_idx], row=m_lo)   # 行级间接读
    B_iter = tile_iterator(ptr_B[problem_idx], col=tile_n*BLK_N)
    acc fp32 = mainloop(A_iter, B_iter)                                      # cp.async + mma.sync
    epilogue_scatter(ptr_D[problem_idx], scatter_D[problem_idx], acc)        # 行级间接写
```

### 3.7 host 编排时序（layer0）

```
forward():
  local self-copy 到对称缓冲 + barrier 清零（cp_stream），record prepare_event
  cp_stream: 启动 AllGather（ring + 点灯）           # 立刻返回
  main_stream: 元数据 kernel（求逆/排序/重基/prepare workspace）
  main_stream: wait(prepare_event)                    # 只等"本地就位+灯已清零"
  main_stream: 发射融合 GEMM（kernel 内自行等灯）
```

## 4. Layer1：GatherRS 的完整机制

### 4.1 结构总览——水平融合

**layer1 是两个 kernel、两条 stream 的水平融合**：

- **GroupedGEMM kernel**（主 stream）：纯本地计算，输出写本地 `gemm_out[M_this_ep, N]`（expert 排序行）。epilogue 里唯一的额外动作是**分层计数置 flag**。
- **Reducer kernel**（高优先级 stream，仅 `RS_BLOCKS`（默认 3）个 CTA）：等 flag → gather topk 行 → 加权求和 → ring ReduceScatter（直接读写各 rank 的对称缓冲）。
- GEMM 的 launch 加 `sm_margin = 用户值 + RS_BLOCKS`，即少用这几个 SM，给 reducer 让位。两 kernel 由硬件调度并发驻留。

### 4.2 N-split：把 N 维切成可提前发货的片

把每个 expert 的 GEMM 沿 **N 维**切成 `n_split` 片（默认 4）：

- `problem_count = E_local × n_split`；problem (e, s) 的形状 `(M_e, N/n_split, K)`，B 指针偏到该 expert 权重的第 s 个列块，D 指针偏到 `gemm_out` 的对应列区间。
- problem 排布按 `[s][e]`：**同一 s 的所有 expert 连续**——这样"第 s 片全部完成"是一个连续计数组。

为什么沿 N：combine 在 M 维做规约（topk 行求和），M 方向没有独立可交付的单元；而输出的各列独立——某个 N 片对所有 expert 算完后，这片列上**所有 token** 都可以立刻规约+通信。n_split 越大重叠越细、GEMM 越碎，默认 4 是权衡值。

### 4.3 GEMM→Reducer 的分层信号

```
barrier[0 .. n_split)        每片的 ready flag（reducer 轮询对象）
problem_counter[problem_count]  每个 problem 的 tile 完成计数
```

epilogue 尾部（每 tile 一次，tid==0）：

```
if ++tile_counter[problem] == 该 problem 的 tile 总数:        # problem 完成
    s = problem 所属的 N 片
    if ++problem_counter_group[s] == 每片的 problem 数:        # 该片全部 expert 完成
        atomic_ref<device,release>(barrier[s]).fetch_add(1)    # 点灯
```

（空输入时 host 直接把 barrier 填 1，防 reducer 卡死。）

### 4.4 Reducer kernel：gather + topk 加权求和 + ring RS

**组织**：`grid = RS_BLOCKS`（默认 3）个 CTA。tile = `128 token 行 × 1024 列`；worker 以 128 线程为一组负责一行的 1024 列，`uint4`（128-bit）向量化访存。

**对称缓冲**：`reduce_buffer[r]`：`[ntokens, N]`（每 rank 一块，ring 的中转站）；`tile_flag[r]`：ring 逐 tile 握手 flag。

**主循环**（write/push 模式，默认）：

```
for s in 0..n_split-1:                            # N 片，串行
  wait(barrier_local[s] == 1)                     # 等本卡 GEMM 完成该片
  for stage in 0..world_size-1:                   # ring RS 的步
    segment = (stage + rank + 1) % world_size     # 本步处理哪个 rank 的 token 段
    for tile in 本段该片的所有 (blk_m, blk_n)，按 CTA 划分:
      载入 routing_idx[该 tile 的 128 行 × topk] 到 smem
      if stage > 0: wait(tile_flag_local[tile] == stage 期望值)   # 等上一跳的部分和到本地
      for 每行 token（组内并行）:
        acc fp32[8] = 0
        for k in 0..topk-1:
            src = smem_idx[row, k]                          # expert 排序行号
            acc += float(gemm_out[src, cols]) * vec_scale[src]   # 本地读 + 加权
        if stage == 0:
            store(reduce_buffer[prev_rank][segment 段, cols], acc)          # 远端写（push）
        elif stage < world_size-1:
            partial = load(reduce_buffer[rank][...])                        # 本地读上一跳部分和
            store(reduce_buffer[prev_rank][...], acc + partial)             # 累加后推给下一跳
        else:
            output[本地行, cols] = acc + load(reduce_buffer[rank][...])     # 最后一步落本地输出
      全 CTA barrier
      sync warp: atomic_store_release_sys(tile_flag[prev_rank][tile], 完成标记)  # 通知下一跳
```

### 4.5 关键要点

- **push 模式的数据方向**：worker 永远**本地读、远端写**（写邻居的 `reduce_buffer` 和 `tile_flag`）。**PCIe 上远端读极慢，必须禁用 pull/read 模式**。
- **topk 求和与跨卡求和的可交换性**：每行先乘 gate 权重再加，所以 ring 上逐 rank 的部分和累加与 topk 合并顺序无关，结果一致。
- **fp32 累加**，最后转回目标精度。
- worker/sync 分工用两个命名 hardware barrier（worker 会合 + 全体会合），sync warp 专职点灯，避免 worker 尾部串行化。
- **EP>1 变体**：先对 `splits` 做 block 内前缀和得本 EP rank 的行区间 `[ep_m_start, ep_m_end)`；gather 时只累加落在区间内的源行——EP 各卡的缺失贡献恰好由 ring 求和补齐。

### 4.6 host 编排时序（layer1）

```
forward_gather_rs():
  group_barrier(所有 rank，确保对称缓冲/flag 可用)
  record(start_event, main_stream); rs_stream.wait(start_event)
  main_stream:  发射 GroupedGEMM（sm_margin 让出 RS_BLOCKS 个 SM）
  rs_stream(高优先级): 发射 Reducer（RS_BLOCKS 个 CTA）
  record(done_event, rs_stream); main_stream.wait(done_event)
  group_barrier；barrier/flag 清零复位
  返回 output
```

## 5. 对称内存与初始化

- **初始化**（每进程一次）：建 CUDA context → rank0 取 NVSHMEM UID → 经 torch.distributed 进程组广播 → 各 rank `nvshmemx_init_attr(UID)`。若不用 NVSHMEM：直接用 cudaIPC。
- **对称缓冲分配**（二选一）：
  - NVSHMEM：`nvshmem_malloc` + `nvshmem_ptr(ptr, peer)`；
  - cudaIPC：本地 `cudaMalloc` → handle 经进程组 all-gather → `cudaIpcOpenMemHandle`（懒启用 P2P）。
- **进程组只做控制面**（handle/UID 交换、host barrier）；数据面全部是 kernel/DMA。
- **跨 rank group barrier**（stream 上的设备级 barrier）：NVSHMEM 用 `nvshmemx_barrier_all_on_stream`；否则自研——对称 flag 上做 ring-token（release store + acquire load 轮询，**不用跨卡 RMW 原子**，PCIe 兼容）。
- buffer 生命周期：绑定算子对象；flag/barrier 每次 forward 前后清零。
