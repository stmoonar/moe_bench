# PK 框架下的路线重估（2026-07-16）

依据：`docs/paper_raw/ParallelKittens...md`（PK 论文）三层决策框架 ×
本机硬件事实（PCIe、无 NVSwitch/multimem、远端原子不可靠）×
方案A 定位数据（tp_run_20260716_070406）。

## 1. PK 框架逐层映射

### 1.1 传输机制（PK §3.1.2）

| 机制 | PK 结论（NVLink） | 本平台 | 裁决 |
|---|---|---|---|
| Copy Engine | 带宽最高但需 ≥256MB 粒度才打满 | 传输单元 4KB 行 | 判负获理论背书（docs/43 +609µs 与粒度判据一致），关档 |
| TMA | 2KB 粒度近峰值；单线程异步；**15 SM 打满 450GB/s** | 唯一高效机制；PCIe 带宽仅 NVLink 5% → 理论上极少 SM 应可打满 | 主力；**当前 24 comm SM 是最大错配** |
| Register op | 128B 粒度但需 76 SM；独有 in-network reduction | 无 NVSwitch → multimem 不存在；远端原子不可靠（docs/08） | 路线在本平台物理不存在 |

### 1.2 调度（PK §3.1.3）—— 方案A 判负的理论解释

PK 明确给出 intra-SM overlap 的适用前提：**通信模式与计算模式对齐**（其
GEMM+RS 例：storer 把刚算完的 output tile 顺手推 peer，通信单元=计算单元，
每 tile 一次 TMA 摊在整个 K 循环上）。我们两层都不满足：

- L0 = token 粒度 gather-scatter（pull_order 消费序），与 GEMM tile 流无关；
- L1 = prered 要跨行块聚 8 行再推，同样不对齐（对齐版=推未归约 tile = 8×
  wire 字节，PCIe 上死路；TMA store_add 远端归约受远端原子不可靠约束，
  同样出局）。

→ PK 判据直接判两层都该 inter-SM。方案A 的 diag 数据（共存税 +226/SM 队列
HoL）是该判据在 PCIe 上的加强版。**架构方向（inter-SM + 转岗）本来就是对
的**；PK 的 SM-partitioning 调优（comm_sms sweep）我们也已在做。

L1 定量补充：PK 完全隐藏判据 **K ≥ sR/2B**。L1 的 K=768（fp8 s=1、
R≈300e12、B≈50e9）→ 阈值 ≈3000 ≫ 768：**L1 wire 结构性藏不满，v1 定案**。

### 1.3 设计开销（PK §3.1.4）

单向同步、预分配目的缓冲、无中转 staging —— pcie_sync 协议三件套已全部
符合，无新动作。

## 2. 核心洞察与路径

**错配不在架构，在"通信占的 SM 数"**。PK：TMA 打满 450GB/s 只要 15 SM；
我们 23.5GB/s 的 pull 占 24 SM——不是带宽需要，是并发组织低效：
`dispatch_persistent` 波同步（20 lane 一起 __syncthreads 等最慢者），槽位
与 lane 绑死。方案A 的 `comm_lane_pull`（per-lane 独立领取/自旋/无同步）
正是高效组织，只是放错了位置——**应跑在专职 comm 块上，不是 GEMM 块里**。

### P1：comm 块 per-lane 自由化 + 压 comm SM 数（首选，改动小）——已落码

- 把 comm_lane_pull 的 per-lane 模式移植回专职 comm 块（每块 ~20 槽全
  per-lane 自由循环，去掉波同步）；
- 扫 TK_COMM_SMS ∈ {4,8,12,16,24}；
- 预期：同样在飞并发用一半 SM 承载 → 让渡税 183 → ~90-120，
  e2e 1709 → **~1620-1650**。

**落码（2026-07-16）**：`tpdisp8::dispatch_persistent_lane` + `kernel_lane` +
`entry_lane`（绑定 `moe_tp_dispatch_gemm_fp8_lane`），开关 `TK_L0_LANE=1`
（默认 0，与 WARP/CE 互斥）。要点：槽线程按 stride-8 铺到 5 个 warp（每
warp 4 条自由循环，避免 20 条挤一个 warp 串行发射）；从全局 `pull_next`
原子领取——严格全局 pull_order 消费序（比波同步版的分块跨步序更贴 gate）；
非槽线程直接到 sync(2) 汇合点等转岗，拉完整块照旧转 GEMM worker；数据面/
计数协议逐字节同构。`time_tp_stages` 已感知（08p1）。脚本步骤：
03p1 正确性门 + 04p1 e2e（512/1024）+ 05p1 lane comm_sms sweep{4,8,12,16,24}
+ 05p1_wave_commsms_4 对照（分离"per-lane 收益"与"少 SM 本身"）+ 08p1 归因。
上机：`STEPS='^00_|^01_|^03f8_|^03p1_|^04f8_|^04p1_|^05p1_|^08f_|^08p1_'
bash tools/run_tp_all.sh`。

### P2：L0 push 化重估（由 P1 数据门控）

- 微基准事实：push 强路径 50.9GB/s **4 SM 打满**（docs/22）；
- 若 P1 后 pull 仍需 ≥12 SM → 重开 tppdisp（fp8 化）：comm SM 4-6，
  让渡税 → ~40，e2e 再 −50~80 → **~1570-1600**；
- 当年 push 判负环境（bf16/无转岗/旧调度）已全变，重审有据。

### P3：sched ~270µs（与 PK 无关，最大单项）

- 占 e2e ~16%；旧计划 C 刀（双流/摊薄）预期 −60~100 → **~1500-1540**，
  逼近修正后的平台上限。

### 关档项

intra-SM（方案A，代码留 TK_L0_WARP/TK_L1_WARP 档案）、CE、register-op/
in-network 全路线、L1 任何重构。

## 3. 风险与验证口径

- P1 的关键假设：pull 的 24-SM 需求主要来自波同步低效而非真实并发下限。
  裁决工具：改造后直接扫 comm_sms，diag_warp 的 l0_default 档可对照；
- P1 若证伪（12 SM 以下 L0 暴露回升）→ 直接进 P2；
- 全程主配置 `configs/tp_rtx_pro5000_4gpu_fp8.yaml`，A/B 只覆盖最小字段；
- 每步带 03 正确性门 + 04 e2e + 08 归因三件套。
