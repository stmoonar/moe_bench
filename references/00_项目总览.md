# 项目总览

## 1. 我们要做什么

在 RTX Pro 5000（sm120）+ PCIe + 4 卡环境下，从头实现一套 MoE 层通信计算融合算子。目标是让跨卡通信（dispatch/combine）与专家计算（Grouped GEMM）在 GPU kernel 内部以 tile 粒度重叠，隐藏通信延迟，从而比"通信和计算串行执行"的 baseline 更快。

**不提供任何参考实现的源码**。本文档系列是全部信息来源——包含背景知识、优化原理、硬件适配要点和 benchmark 接入契约。具体实现方案由 Agent 自行设计、迭代、验证。

## 2. 硬件环境

| 维度 | 规格 |
|---|---|
| GPU | RTX Pro 5000，sm120 架构（消费级 Blackwell） |
| 互连 | PCIe，无 NVLink；连续两卡共享同一 PCIe Switch |
| 测试卡数 | 4 |
| 推荐卡组合（按优先级） | 9,11,13,15 > 8,10,12,14 > 1,3,5,7 > 0,2,4,6 |
| CUDA | 12.8+（需编译 `sm_120`） |

### 2.1 与源设计环境的差异

COMET 原始设计针对 A100（sm80）+ NVLink。目标硬件的关键差异：

- **互连**：PCIe ~25-60 GB/s vs NVLink 数百 GB/s，通信慢一个量级
- **P2P**：消费卡 P2P 可能被驱动限制，需实测验证
- **跨卡原子**：PCIe 上 `cudaDevP2PAttrNativeAtomicSupported` 大概率为 false
- **Tensor Core**：sm120 有自己的第 5 代 tensor core，非 wgmma（sm90）非 tcgen05（sm100）
- **CUTLASS**：grouped GEMM × sm120 组合成熟度未知，需实验验证
- **显存**：16-32 GB GDDR7，对称缓冲预算更紧

## 4. 代码约束

- **不提供 COMET/flux 源码**，依据原理文档自行实现
- 必须接入 moe_bench 的 `DistributedScheme` 接口
- 必须通过 moe_bench 自动正确性校验
- `run()` 需无副作用、分配稳定（虽然分布式模式下不用 CUDA Graph，但仍需重用 setup 中分配的缓冲）
- 每次测试前检查 GPU 是否空闲，不要在有任务进行的卡上跑测试

## 5. 成功标准

1. **正确性**：moe_bench `verify` 列全部 `ok`（FP8 容差 atol=3.5e-2, rtol=3.5e-2）
2. **性能**：单层延迟低于 serial baseline（PCIe 参照档 1.2x-1.5x 加速）
3. **鲁棒性**：边界场景通过（某专家 0 行、极端倾斜路由、token 数不能整除等）

## 6. 性能预期

- COMET 论文（8xH800 NVLink）：单层平均 1.96x，隐藏 86.5% 通信延迟
- 8xL20（PCIe ~25GB/s，最接近目标硬件的参照）：均值 1.19x-1.46x
- **迁移后的合理预期应参考 PCIe 档**，而非 NVLink 数字
- 收益与通信占比 x 重叠效率成正比；通信时间超过计算时间时，重叠只能隐藏到"计算时长"为止
