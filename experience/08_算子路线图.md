# 08 算子路线图

> 按算子给出推荐实施路线（每条路线内部按侵入性递进），以及统一决策树。

## 0. 统一决策树（任何算子先走一遍）

```text
1. 测通信占比 → <10%？耗时降低天花板 ~4.8%，暂缓
2. 算 num_waves → ≤1？tile 级方案出局，考虑 token/seq 切分或不重叠
3. P2P/对称内存可用？否 → 只能走 signal+NCCL 低侵入路线
4. shape 规则且稳定？否 → 优先 stream 级/chunk 级方案，缓上 fused kernel
5. 数据流含动态路由/gather？是 → 走 MoE 专用路线（依赖分解+重排先行）
6. 以上都通过 → 按下述算子路线递进，每级用干扰系数与 overlap 效率做 go/no-go
```

## 1. AllGather + GEMM（consumer 等 producer）

**级 1（低侵入）**：通信按 rank 分片走 copy engine/NCCL，每片完成置 signal；GEMM 不改，按 wave group 或 rank 片触发后续消费。
**级 2（prologue 融合，主推）**：
- host/copy stream 按 ring 或 all2all 顺序分发分片，逐片置位；GEMM prologue 里 producer warp 按"tile 覆盖的分片区间"等信号（区间可能跨 2 片，逐片等）。
- swizzle：各 rank 从本地分片对应的 tile 行开始环形推进（首波零等待）；预先把本 rank 信号置位。
- 通信 chunk 从"rank 分片"往下按减半搜索；push/pull、ring 顺序按拓扑 profile。
**级 3**：多节点两跳（跨节点先到同 index rank，节点内再扇出），节点间访问顺序用拉丁方错开。
**风险**：小 M/decode 时 one-wave；此时改 token/sequence 二分（wave 对齐）或不融合。

## 2. GEMM + ReduceScatter（producer 推 consumer）

**级 1**：GEMM epilogue 按 tile 置"就绪"计数，按段触发 NCCL RS（需要段内行按目标 rank 分组的行级重排，融进写出）。
**级 2（epilogue/DMA 融合，主推）**：
- pull 模式两级握手：epilogue 写完本地 tile 置 flag；每 CTA 一个 DMA warp 从对应远端拉"属于我的"镜像 tile 到 smem，本地归约，计数攒满 world_size 收尾。
- swizzle：rank 偏移错开写/拉目标 + **本 rank 归属的 tile 最后算**（尾部零暴露）。
- 数据类型注意：远端原子加的类型支持不一致，不支持就"本地归约 + 传输"两步；归约顺序的非确定性对训练可复现有影响。
**级 3**：跨节点两级——节点内先归约，聚合后单份发往远端节点同 index GPU。
**风险**：M 必须能被 tile×world_size 整除（pad 策略与 tile 选择的交互要小心）；m 极小时输出写出效率崩塌，直接回退。

## 3. AllReduce + Norm/residual

- 首选把 AllReduce 分解为 RS + AG，且**Norm 在 RS 后的 1/N 分片上就地做**（计算量÷N），AG 广播已归一化结果。
- 有 NVSwitch 在网归约（multimem）时：RS 用 ld_reduce、AG 用多播 store，融合 kernel 只给 2~8 个 SM，与另一半 batch 的计算流交错（token 二分 + wave 对齐）。
- 无 NVLS：退到常规 RS/AG + 融合 elementwise，通信 SM 照样少量化。
- 生效门槛：≥千级 token 才启用切分，decode 小 batch 回退到"不重叠但融合"的单 kernel。

## 4. MoE dispatch + expert GEMM（layer0）

1. **metadata 先行**：token 按 (source_rank, expert) 排序，子问题化；处理顺序 circular shift 本地优先。routing 不变时缓存全部布局（handle 化），跳过重算与 CPU 同步。
2. 通信：分片经 copy stream / 通信 kernel 拉取，每 rank 分片到达置一个 flag（rank 级聚合信号）。
3. GEMM：grouped GEMM 保持高效 tile，不为路由切小；producer warp 在切换子问题时等对应 rank flag，且对下一个子问题做预取式等待。
4. 跨节点：dispatch 走两跳转发 + 环形队列协议（见 05/07 篇），发送窗口 ≤ 接收缓冲一半。
5. decode 低延迟：per-expert QP + 双缓冲 + 收发两阶段钩子（传输期 0 SM），token 上限固定。

## 5. expert GEMM + combine/RS（layer1）

1. 沿 **N 维**切列块（7~9 份量级），GEMM 的 problem 遍历序改"列块优先"，跨过列块边界时计数。
2. 通信角色：grid 末尾专职通信 CTA（28/132 量级起步）等"全部计算 CTA 越过列块 k"后 gather 该列块的 topk 行、FP32 累加、写目标 rank（TP 直写 / EP 系统级原子加）。
3. 全员收尾：计算 CTA 算完回头帮做最后一个列块的通信。
4. 防死锁细节：grid < SM 数时补计数；空转 CTA 也补 arrive；调度就绪 flag 防两 kernel 互等。
5. top-k 大时单独 profile 归约的原子累加吞吐，必要时先本地聚合再跨卡。

## 6. 序列并行 / attention 类

- sequence 维二分（可不等分，比例按两块承担的通信量配平），causal 约束下后块 attention 等前块 KV 落地；MLP 段自由交错。
- 收益强依赖互联：PCIe 35~48%，NVLink 仅 0~25%——NVLink 机器优先做 TP 算子而不是 seq 切分。

## 7. 各级验收标准（通用）

```text
每级必测：T_compute_alone、T_comm_alone、T_overlap_total
overlap 效率 = (T_c + T_m - T_total) / min(T_c, T_m)     目标：级1 ≥0.5，级2/3 ≥0.8
计算干扰 = T_compute@overlap / T_compute_alone            目标：≤1.05（NVLink）/ ≤1.1（PCIe）
通信干扰 = T_comm@overlap / T_comm_alone                  目标：≤1.2
任何一项不达标 → 先修干扰（SM 预算/chunk/优先级），不要急着进下一级
```
