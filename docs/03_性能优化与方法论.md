# 性能优化与方法论

## 1. 关键性能演进

### TP BF16

| 阶段 | T=512 结果 | 主要变化 |
|---|---:|---|
| TP 首轮 | 3613µs（0.73× serial） | ring 拉取序与 block-per-job 导致两处调度串行 |
| 消费序 + dispenser | 2363µs | `pull_order` 对齐消费序；全员 dispenser 消除 wave 排队 |
| comm_sms 定档 | 约 2290µs | U 型曲线拐点确认在 24 |
| L0 转岗 + GLU 融合 | 2125µs | 转岗约 −68µs；SwiGLU epilogue 约 −83µs |
| BF16 阶段收官 | 2116µs vs serial 2624 | 1.24×；T=1024 为 3781 vs 5020（1.33×） |

NE=256 需要单独看：`ROW_BLOCK=64` 在 TP 中把 5427µs 降到约 4950µs，并使该档从慢于
serial 翻为约 1.07×；它不是所有 shape 的默认值。

### TP FP8

| 阶段 | T=512 | T=1024 | 收益来源 |
|---|---:|---:|---|
| P2：L0 FP8 | 1920 | 3239 | token/AG/W1 FP8，线上字节减半 |
| token 量化 kernel 化 | 1879 | 3180 | torch 五个小 kernel 合并为一个 rowgroup kernel |
| P3：L1 FP8 | 1756 | 3017 | act/W2 FP8，T=512 净赚约 129µs |
| schedule int32 | **1708** | **2970** | 三处 argsort key int64→int32，约 −48µs |

对应 serial FP8 为 2074/4025µs，即历史最好加速 1.21×/1.36×。这些是旧迭代配置下的稳定
结果，最终报告仍需按当前主配置全量重跑。

## 2. 当前性能账

BF16 T=512 阶段账约为：

```text
2116 = sched 268 + tok_copy 30 + L0 1170 + L1 691 + final_red 20 - 跨段重叠
```

FP8 在 L1 落地前的未隐藏通信约 190µs：L0 AG 基本完全隐藏，L1 尾约 108µs，final reduce
约 20µs，schedule 内 NCCL gather 约 40µs，两次 PCIe 屏障约 20µs。另有约 264µs 的
“让渡税”——通信占用 SM 后导致 GEMM 变慢，它不是裸露通信。

历史估计的平台合理上限约 1660µs；1708µs 距离上限只剩 final reduce 与 L1 尾部的小量空间。
在不改变通信引擎/硬件前提时，继续堆复杂协议的回报已经很低。

## 3. 已验证有效的通用优化

1. **生产/到达顺序必须对齐消费顺序。** L0 从 ring 顺序改为 min-slot/expert-major 后，
   3613→2363µs 的大头得以回收。
2. **常驻块 + dispenser 优于 block-per-job。** 大共享内存 kernel 的 block wave 会把逻辑
   并行退化为排队；原子 claim 可以跨 task 连续供给工作。
3. **完成通信后转岗计算。** 固定 comm SM 只在通信阶段有价值，完成后加入 GEMM 可降低
   SM 让渡成本。
4. **逐元素后处理放进 accumulator epilogue。** SwiGLU 融合既省 kernel 和显存流量，
   还避免 BF16 中间舍入。
5. **通信粒度至少能摊薄一次 RTT。** L1 v2 的 1 token×1KB push 让性能从 691 退到
   1294µs；16-token 组批回收了 84% 回退。
6. **量化也必须 kernel 化/融合。** torch token 量化链把 `tok_copy` 从 30 拉到 112µs；
   单个 rowgroup kernel 将它压到 24µs。

## 4. 调优流程

- **公平口径先行**：schedule、量化、路由 gather 都必须计入 `run()`；serial 的调优状态和
  配置必须写入 manifest。历史 EP 曾因漏计 schedule 虚报 1.48×。
- **先分段再改代码**：`time_tp_stages.py` 的 fused/alone/nb/cm 对照用于拆出 GEMM、让渡、
  真正尾部和协议成本。性能指标必须能闭账。
- **每项优化有独立 A/B 开关**：例如 `TK_L0`、`TK_L0_GLU`、`TK_L1_FP8`、CE 开关。
  这样既可定价，也能在失败时二分。
- **先写预期账，再看偏差**：偏差本身用于归因。L1 v2 首测多出的 603µs与“每 job 一次
  wait”的理论直接闭合，从而快速定位粒度病。
- **小回路用 FOCUS/STEPS，全量回归留里程碑**：快速轮只裁决一个假设，最终必须回到唯一
  主配置。
- **波动先取证**：共享机器出现过 serial 与 tktp 同时双峰游走；看 per-step clock、重复跑
  一致性和 rank max，不能挑孤立最小值作为终数。

## 5. 如何引用历史数字

原始数据和每轮假设位于归档 20~45。引用时至少同时记录：commit、卡组、precision、T/rank、
warmup/iters、所有 `TK_*` 覆盖、serial 是否调优以及结果目录。当前正式口径以
`configs/tp_rtx_pro5000_4gpu_fp8.yaml` 为准。
