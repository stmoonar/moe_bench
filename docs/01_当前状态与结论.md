# 当前状态与结论

## 1. 当前目标与默认口径

当前主线是 RTX PRO 5000（SM120）PCIe 四卡上的 TP MoE 通算融合实现 `tktp`，与 vLLM
串行通信、计算实现对比。唯一默认测试配置是
[`configs/tp_rtx_pro5000_4gpu_fp8.yaml`](../configs/tp_rtx_pro5000_4gpu_fp8.yaml)：

| 项 | 默认值 |
|---|---|
| 模型形状 | hidden=4096，intermediate=3072，E=64，TopK=8 |
| 并行 | TP，world size=4 |
| 精度 | FP8，token 1×128 group，weight 128×128 block |
| 负载 | 512 token/rank，四卡共 2048，balanced routing |
| 计时 | warmup=20，bench=50 |
| 正确性 | 默认开启 |

测试必须从 `/workspace` 运行 `python -m moe_bench...`，并显式传主配置。专用脚本若不能直接
读取 YAML，必须逐项对齐并只记录最小覆盖。完整约束见 [05_测试与调试指南.md](05_测试与调试指南.md)。

## 2. 已经收敛的实现

- L0：源 token FP8 group 量化、FP8 AllGather 数据面（源端 posted-write push + 收端按
  消费序本地 scatter）、persistent dispenser grouped GEMM、FP32 accumulator 上的
  SwiGLU epilogue。
- L1：激活 FP8 group 量化、FP8 W2 grouped GEMM、本地 top-k 预归约、SM 驱动的细粒度
  ReduceScatter push、水位信号和最终本地归约。
- 调度：GPU builder 计入 `run()`；key 已从 int64 安全瘦身为 int32；host/GPU builder 有
  逐元素裁决。
- 协议：跨卡完成检测使用“本地原子选举唯一写者 + `st.release.sys` 定值信号 + 本地
  acquire 自旋”，不依赖远端原子 RMW。
- 工程：`tools/run_tp_all.sh` 当前每一步各自起一次独立的四进程/NCCL 生命周期
  （早期曾有跨 case 复用同一进程组的批量回归工具，已随 slim 分支移除）；每步独立
  setup/close 并保留 JSON 输出，单步超时或失败不影响其余步骤。

实现入口与数据流见 [02_实现架构.md](02_实现架构.md)。

## 3. 性能状态

以下是历史收官轮的稳定数值，用于说明优化已经达到的量级，不是基于当前 `warmup=20` 主配置
重新生成的最终报告：

| 口径 | T=512 | T=1024 |
|---|---:|---:|
| tktp FP8 | **1708µs** | **2970µs** |
| vLLM serial FP8 | 2074µs | 4025µs |
| 相对 serial 的耗时降低 | **17.6%** | **26.2%** |
| tktp BF16 历史对照 | 2116µs | 3781µs |
| vLLM serial BF16 历史对照 | 2624µs | 5020µs |

FP8 T=512 从 1920µs 依次经过量化 kernel 化、L1 FP8、schedule int32 瘦身降到 1708µs。
平台合理上限估计约 1660µs，主优化线已经进入个位数百分比的边际区。详细演进见
[03_性能优化与方法论.md](03_性能优化与方法论.md)。

这些数字有四个限制：主要性能演进来自早期 16 卡服务器的 `9,11,13,15` 等卡组，而当前环境
是 8 卡机器；历史轮 warmup 多为 5；共享机器存在可复现的间歇干扰；7 月 15 日那轮 suite
的记录（原 `configs/runs/tp_run_20260715_124912.yaml`，已随 slim 分支移除，见 `fp8_tp`
分支历史提交）里有 Triton 导入错误，不能直接充当最终结果。因此最终对外数字必须用当前
主配置重新全量回归。

## 4. 尚未闭环

1. 在空闲卡组上先跑 `QUICK=1`，再跑完整 `tools/run_tp_all.sh`，生成当前主配置下的
   BF16/FP8 双口径终数；suite 异常时用 `STEPS` 过滤到失败步骤单独重跑定位。
2. FP8 正确性口径仍需裁决：当前 rel_err 约 `4.28e-2`，高于旧元素级 `3.5e-2` 容差。
   可选方案是将 FP8 容差校准到 `5e-2`，或从数据层直接生成交织后的 W1 量化布局，消除
   “反量化 → 交织 → 重量化”的二次量化。未裁决前不能把性能结果称为完整正确性闭环。
3. 用当前配置和空闲优先卡组重做最终报告，并把所有覆盖写入结果目录
   （`tp_test_results/tp_run_<时间戳>/`）、`HANDOFF.md` 和提交信息。
