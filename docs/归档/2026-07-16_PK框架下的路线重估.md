# PK 框架下的路线重估（2026-07-16）

依据：`docs/paper_raw/ParallelKittens...md`（PK 论文）三层决策框架 ×
本机硬件事实（PCIe、无 NVSwitch/multimem、远端原子不可靠）×
方案A 定位数据（tp_run_20260716_070406）。

## 1. PK 框架逐层映射

### 1.1 传输机制（PK §3.1.2）

| 机制 | PK 结论（NVLink） | 本平台 | 裁决 |
|---|---|---|---|
| Copy Engine | 带宽最高但需 ≥256MB 粒度才打满 | 传输单元 4KB 行 | 判负获理论背书（docs/43 +609µs 与粒度判据一致），关档 |
| TMA | 2KB 粒度近峰值；单线程异步；**15 SM 打满 450GB/s** | 唯一高效机制；PCIe 带宽仅 NVLink 5% → 理论上极少 SM 应可打满 | 主力；**当前 24 comm SM 是最大错配** |
| Register op | 128B 粒度但需 76 SM；独有 in-network reduction | 无 NVSwitch → multimem 不存在；远端原子不可靠（docs/08） | 路线在本平台物理不存在 |

### 1.2 调度（PK §3.1.3）—— 方案A 判负的理论解释

PK 明确给出 intra-SM overlap 的适用前提：**通信模式与计算模式对齐**（其
GEMM+RS 例：storer 把刚算完的 output tile 顺手推 peer，通信单元=计算单元，
每 tile 一次 TMA 摊在整个 K 循环上）。我们两层都不满足：

- L0 = token 粒度 gather-scatter（pull_order 消费序），与 GEMM tile 流无关；
- L1 = prered 要跨行块聚 8 行再推，同样不对齐（对齐版=推未归约 tile = 8×
  wire 字节，PCIe 上死路；TMA store_add 远端归约受远端原子不可靠约束，
  同样出局）。

→ PK 判据直接判两层都该 inter-SM。方案A 的 diag 数据（共存税 +226/SM 队列
HoL）是该判据在 PCIe 上的加强版。**架构方向（inter-SM + 转岗）本来就是对
的**；PK 的 SM-partitioning 调优（comm_sms sweep）我们也已在做。

L1 定量补充：PK 完全隐藏判据 **K ≥ sR/2B**。L1 的 K=768（fp8 s=1、
R≈300e12、B≈50e9）→ 阈值 ≈3000 ≫ 768：**L1 wire 结构性藏不满，v1 定案**。

### 1.3 设计开销（PK §3.1.4）

单向同步、预分配目的缓冲、无中转 staging —— pcie_sync 协议三件套已全部
符合，无新动作。

## 2. 核心洞察与路径

**错配不在架构，在"通信占的 SM 数"**。PK：TMA 打满 450GB/s 只要 15 SM；
我们 23.5GB/s 的 pull 占 24 SM——不是带宽需要，是并发组织低效：
`dispatch_persistent` 波同步（20 lane 一起 __syncthreads 等最慢者），槽位
与 lane 绑死。方案A 的 `comm_lane_pull`（per-lane 独立领取/自旋/无同步）
正是高效组织，只是放错了位置——**应跑在专职 comm 块上，不是 GEMM 块里**。

### P1：comm 块 per-lane 自由化 + 压 comm SM 数（首选，改动小）——已落码

- 把 comm_lane_pull 的 per-lane 模式移植回专职 comm 块（每块 ~20 槽全
  per-lane 自由循环，去掉波同步）；
- 扫 TK_COMM_SMS ∈ {4,8,12,16,24}；
- 预期：同样在飞并发用一半 SM 承载 → 让渡税 183 → ~90-120，
  e2e 1709 → **~1620-1650**。

**落码（2026-07-16）**：`tpdisp8::dispatch_persistent_lane` + `kernel_lane` +
`entry_lane`（绑定 `moe_tp_dispatch_gemm_fp8_lane`），开关 `TK_L0_LANE=1`
（默认 0，与 WARP/CE 互斥）。要点：槽线程按 stride-8 铺到 5 个 warp（每
warp 4 条自由循环，避免 20 条挤一个 warp 串行发射）；从全局 `pull_next`
原子领取——严格全局 pull_order 消费序（比波同步版的分块跨步序更贴 gate）；
非槽线程直接到 sync(2) 汇合点等转岗，拉完整块照旧转 GEMM worker；数据面/
计数协议逐字节同构。`time_tp_stages` 已感知（08p1）。

**实测裁决（tp_run_20260716_073019）**：

| 档位 | med (µs) | 结论 |
|---|---|---|
| 波同步基线 @24 | 1709 | — |
| lane @24 | **1681**（另一步 1693） | **全档赢，翻默认（TK_L0_LANE 默认 1）** |
| lane @16/@12/@8/@4 | 1775/1808/1904/2633 | 拐点未左移，16 SM 即回升 |
| 波同步 @4 对照 | 3814 | lane@4 快 1181µs——组织效率差距巨大 |
| lane T=1024 | **2831** | vs 2935（−104，−3.5%） |

- 正确性 rel_err 4.27e-2 同水位；lane 在每个 comm_sms 档位都严格优于波同步；
- **但 P1 的核心假设被证伪**：24 SM 不是波同步低效的补偿——pull 弱路径 RTT
  受限，~480 在飞并发（24 块×20 槽）是真实需求（docs/04 "FP8 后减少
  comm_sms 单调劣化"的根因即此）。压 comm SM 数必须换 push 强路径
  （posted write 无往返，4 SM 打满 50.9GB/s）→ **P2 门控触发**；
- 待查项：默认路径的 08f stages 连续两轮失真（full 3238/3983 vs bench
  1709），lane 路径的 08p1 却准确（1812 vs 1808）——只影响归因工具。

### P2：L0 push 化重估（由 P1 数据门控）——已落码

- 微基准事实：push 强路径 50.9GB/s **4 SM 打满**（docs/22）；
- P1 裁决触发门控（拐点未左移，pull 的 ~480 在飞并发是 RTT 受限的真实
  需求）→ fp8 + lane 组织重做（非复活 bf16 tppdisp）；
- 预期 comm SM 24 → ~8（4 push + ~4 scatter），让渡税 → ~50-70，
  e2e → **~1570-1610**。

**落码（2026-07-16，TK_L0_PUSH=1，默认 0）**：`tpdisp8::pglobals` +
`push_lane`/`scatter_lane`/`kernel_push`/`entry_push`（绑定
`moe_tp_dispatch_gemm_fp8_push`）。设计：

- **源侧 push lane**（前 `TK_L0_PUSH_SMS`=4 个 comm 块，per-lane 组织）：
  按 `push_order`（即各 dest 的消费序，canonical 布局全 rank 一致）把自己
  的量化行+scale 推到 3 个 peer 的 `ag_staging` 平面（plane=源 rank 单写
  者），每 token `store_async_wait` → `__threadfence_system` →
  `st.release.sys` 写 per-token 到达 flag（值=seq，单调免清零）——
  T6-v1 已验证协议的逐 token 版；
- **收侧 scatter lane**（其余 comm 块）：严格 pull_order 领取；远端 token
  本地 acquire 自旋等 flag 后**从本地 staging 读**（~0.5µs，无 PCIe RTT
  ——SM 数可压的结构性原因），自己分片直读 pre_tokens；scatter 8 槽 +
  行块计数与 pull 逐字节同构；两类块干完 sync(2) 转岗 GEMM；
- **跨迭代安全**：双 pcie_device_barrier 已保证 peer 完成上迭代 scatter
  后本 rank 才覆盖其 staging（等价 pre_tokens 保护）；seq = `_l0_seq`
  当前值（每迭代 +2，单调）；
- **依赖无环**：GEMM gate ← scatter ← flags ← peer push（push 只依赖
  本地量化数据）；
- scheme：`TK_L0_PUSH`（优先级高于 lane）/`TK_L0_PUSH_SMS`；
  GPU sched 在 push 模式重建 push_order；stages 工具已感知；
- 脚本：03p2 门 + 04p2 e2e（512/1024）+ 05p2 comm_sms sweep{6,8,10,12,16,24}
  + 05p2b push_sms sweep{2,4,6}@8 + 08p2 归因。

**实测裁决（tp_run_20260716_075314）**：

| 档位 | med (µs) | 结论 |
|---|---|---|
| push @24（psms4） | **1629** | vs lane 1682 = −53，**双档全赢翻默认（TK_L0_PUSH 默认 1）** |
| push T=1024 | **2777** | vs lane 2830 = −53 |
| sweep 6/8/10/12/16 | 2513/1875/1752/1749/1731 | **拐点仍 24 未左移** |
| psms @comm8：2/4/6 | 1750/1875/2518 | **push 2 SM 即饱和**，SM 应尽量给 scatter |

- 正确性 rel_err 4.28e-2 同水位；当前最好口径 **1629/2777**，vs serial fp8
  2074/4030 = **耗时降低 21.5%/31.1%**；
- wire 彻底离开关键路径（posted write 兑现）；**瓶颈转移到收侧本地 scatter
  的 per-token 串行等待**：每 token 8 个 TMA scatter store + store_async_wait，
  单 lane 周期 ~10µs 级——scatter SM 4→20 的 246µs 弹性与此吻合，拐点不
  左移的原因已从"PCIe RTT"换成"本地 scatter 吞吐组织"；
- **P2.5：warp 协作式 scatter**——每 warp 一个 token，32 lane 分工
  搬 128B 段（staging→8 槽全本地 HBM，纯 LSU 向量读写全流水，无 TMA/
  mbarrier/per-token wait），fence 复用 signal_epilogue 的"全员 threadfence
  → sync → 单线程 red"已验证模式；预期 scatter 吞吐数倍，comm SM 压到
  8-12 或同 SM 数再挤 50-100µs。

**P2.5 落码（2026-07-16，TK_L0_SCAT_WARP=1，默认 0）**：
`tpdisp8::scatter_warp` + `kernel_push<SCAT_WARP>` 模板分支。要点：

- scatter 块（cb ≥ push_sms）9 个 warp 全员按 pull_order 领 token，
  无 smem/semaphore；每 token：lane 0..7 读槽表 + lane 0 acquire 自旋等
  到达 flag → `__syncwarp`（与 pcie_sync::wait_slot 后接块同步的既有模式
  同构）→ 32 lane 各搬 128B 段（8×uint4 寄存器中转）写 8 个槽 + 每 lane
  一个 scale float → 全员 `__threadfence` → `__syncwarp` → lane 0..7 各发
  自己槽的 `red.release` 计数；
- push 块不变（slot 线程 TMA push）；psms=2 已实测饱和，P2.5 步骤统一
  `TK_L0_PUSH_SMS=2` 把 SM 让给 scatter；
- 脚本：03p25 门 + 04p25 e2e（512/1024）+ 05p25 comm_sms sweep
  {4,6,8,12,16,24}（warp scatter 吞吐应数倍于 lane 版 → 拐点应真正左移）
  + 08p25 归因。上机：
  `STEPS='^00_|^01_|^03f8_|^03p25_|^04f8_|^04p2_|^04p25_|^05p25_|^08p25_'
  bash tools/run_tp_all.sh`。

### P3：sched ~270µs（与 PK 无关，最大单项）

## 3. 风险与验证口径

- P1 的关键假设：pull 的 24-SM 需求主要来自波同步低效而非真实并发下限。
  裁决工具：改造后直接扫 comm_sms，diag_warp 的 l0_default 档可对照；
- P1 若证伪（12 SM 以下 L0 暴露回升）→ 直接进 P2；
- 全程主配置 `configs/tp_rtx_pro5000_4gpu_fp8.yaml`，A/B 只覆盖最小字段；
- 每步带 03 正确性门 + 04 e2e + 08 归因三件套。
