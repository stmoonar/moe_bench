# 37 FP8 路径:收益分析与分阶段实现计划(分支 fp8_tp)

> 量化方案(用户指定,DeepSeek 式):**token 1×128 group 量化(e4m3 +
> 每组 fp32 scale),weight 128×128 block 量化**。harness 现成度很高:
> `Precision.FP8` + `per_block_cast_to_fp8`(权重块量化)+ vllm serial 的
> w8a8 quant_config + fp8-aware reference 对拍都已在位。

## 1. 收益分析(基于 bf16 实测账,T=512)

### 1.1 我们的融合算子(逐项)

| 项 | bf16 实测 | fp8 预估 | 依据 |
|---|---:|---:|---|
| L0 GEMM | 969 | **~510-560** | mma e4m3 m16n8k32 吞吐 2×(experience/12);扣 per-128K 重标定 ~5-10% |
| L0 让渡/暴露 | ~200 | **~110-130** | 让渡 ∝ GEMM 时长;AG 字节减半(8KB→4KB+128B/token)进一步松 |
| L1 GEMM | 508 | **~270-300** | 同上 |
| L1 尾 | ~183 | ~180 | push/combine 保持 bf16(归约精度),字节不变 |
| act 量化(新增) | — | **+30-40** | v0 独立 kernel(25MB 读 12.5MB 写);P3 融进 GLU epilogue 后趋 0 |
| token 量化(新增) | — | +10-15 | 融进 tok_copy(源端一次) |
| sched/tok_copy/final_red | ~318 | ~318 | 不变 |
| **e2e** | **2116** | **~1420-1550** | 重叠项按比例折算 |

### 1.2 serial 基线(vllm w8a8 block fp8 triton)

serial = AG(bf16 token,**不减半**——vllm 在算子内部才量化)+ fused_experts
fp8 + RS(bf16)。bf16 serial 2624 中 GEMM ~2000、通信 ~600;triton 的 fp8
block GEMM 在 sm120 未调优,通常拿不满 2×(预计 1.4-1.7×)→
**serial fp8 ≈ 1800-2100(P0 实测定标)**。

### 1.3 结构性判断

- **我们的 fp8 优势比 bf16 阶段更大**:AG 字节我们能减半(源端量化后传
  fp8+scale),serial 不能;GEMM 提速两边同享;
- **预期比率 ≈ 1.25-1.40×**,绝对时延 2116 → ~1500(−30%);
- PCIe 平台"FP8 传输是头号杠杆"(experience/12 §4)在 TP 上打了折扣
  (TP 通信占比 ~23%),但 AG 减半 + GEMM 减半仍是全局最大的一刀;
- 风险点:fp8 GEMM 的重标定(per-128K fp32 rescale)在 warp-mma 路径上
  的开销、triton serial 未调优导致比率虚高(报数时注明,或对 serial 也
  跑 TP-T3 式调优)。

## 2. 量化布局设计(对齐现有 kernel 结构)

- **权重**:data.py 已产 (E, ⌈N/128⌉, ⌈K/128⌉) fp32 scales + fp8 块;
  setup 时转置成 x@W 布局(E, K, N)与 GLU 列交织(scale 网格同步交织:
  [gate_scale64…] 交织粒度 128 与 scale 块对齐——**列交织单位从 64 提到
  128 需评估**:GLU 配对要求 gate/up 同 tile,fp8 下 COL_BLOCK=128 tile
  含 gate64|up64 → scale 块 128 跨 gate/up 边界 ✗。解法:w 量化按交织后
  布局重新做(per_block_cast 作用在交织后的 (K,2N) 上),scale 块自然
  对齐 tile,数值等价(块内元素换了邻居,scale 是块内 max,交织后块
  混 gate/up 的 max——仍正确只是 scale 稍保守)。
- **token/act**:1×128 group(K 维),scale (rows, K/128) fp32。
  L0 的 A=gathered(K=H=4096,32 组/行);L1 的 A=act(K=inter=768,
  6 组/行)。
- **GEMM 累加**:stage 的 K 块从 64 提到 128(fp8 A/B tile 128×128 各
  16KB,3 stage=96KB 恰好贴 99KB 预算),**每 stage 恰好一个 scale 块**:
  fp32 子累加器算完一个 stage → acc_total += acc_stage × (a_scale[row]
  × b_scale[kblk,cblk]),a_scale 每行不同(smem 预载一列)。
- **输出**:L0 出 bf16 act(GLU epilogue 不变,P3 再融量化);L1 出 bf16
  expert_out;push/combine/final_reduce 全部保持 bf16 —— 通信协议零改动。

## 3. 分阶段计划(每阶段一个 zip 回流)

| 阶段 | 内容 | 裁决 |
|---|---|---|
| **P0(本轮)** | run_tktp --precision fp8;脚本加 serial fp8 基线步(03f 对拍 + 04f t512/t1024);经验总结(docs/36)+ 本计划 | serial fp8 实测定标;fp8 数据管线全通 |
| **P1** | `grouped_gemm_sm120_fp8` 模板(K-stage 128 + per-stage 重标定 + per-row a_scale)+ `gg::entry_fp8` 单卡入口 + 对拍 torch/deep_gemm 参考 | 单卡 fp8 GEMM 对拍 + TFLOP/s(目标 ≥1.8× bf16) |
| **P2** | L0 集成:源端 token 量化(融进 tok_copy)、fp8 AG(pre_tokens/scales pgl)、scatter 扩 scales、L0 fp8 GEMM + GLU(fp32 epilogue 不变) | 03 对拍(fp8 容差)+ L0_fused 归因 |
| **P3** | L1 集成:act 量化(v0 独立 kernel → v1 融 GLU epilogue)、L1 fp8 GEMM;comm_sms/RB 重扫(拐点会移) | e2e vs serial fp8;全档 sweep |
| **P4** | 调优轮:fp8 下的 comm_sms、GRP、stage 数;报终数(bf16 + fp8 双口径) | 里程碑全量回归 |
