## 信息优先级

发生冲突时按以下顺序处理：

1. `AGENTS.md` 的协作和测试硬约束；
2. `configs/tp_rtx_pro5000_4gpu_fp8.yaml` 的正式默认口径；
3. `HANDOFF.md` 顶部的最新进展和待办；
4. 本目录的收敛文档；
5. git 历史中的过程记录——主要在 `fp8_tp`（以及方案A专项的 `comm_warp`）分支的
   `docs/归档/` 目录，按时间形成的逐轮记录未被删除，只是不再出现在当前工作树。

历史结果使用过不同卡组、warmup、分支和临时覆盖，引用数字时必须同时核对原文与
提交记录，不能覆盖当前主配置口径。

> **平台事实不是跨机器常量。** [04_平台边界与负结果.md](04_平台边界与负结果.md)
> 中记录的带宽、RTT、最佳 `comm_sms` 和性能负结果主要来自早期 16 卡服务器及其卡组；
> 当前协作环境是 8 卡机器。即使 GPU 型号相同，PCIe switch、NUMA、ACS/IOMMU、BIOS、
> driver、时钟和卡组位置也会改变结论。换机器或换拓扑后按
> [04_平台边界与负结果.md](04_平台边界与负结果.md#1-事实的三个层级) 重新定标。

## 后续维护规则

- 当前事实和最终裁决更新到对应主题文档，不再为每一轮新增一个顶层 `docs/NN_*.md`。
- 单次实验的完整参数写入结果目录（`tp_test_results/tp_run_<时间戳>/`）、
  `HANDOFF.md` 和提交信息；不再使用已删除的 `configs/runs/` manifest 目录。
- 每次进展仍同步写 `HANDOFF.md`，但只在顶部追加摘要和指向收敛文档/结果目录的链接。
- 负结果不删除：先把结论写入 [04_平台边界与负结果.md](04_平台边界与负结果.md)，
  原始证据留在 git 历史提交中。
