## 2. 关键洞察:L1 的通算重叠是 SM 零和,真能藏的只有线上时间

两版的账并排看(alone@110SM → fused@86SM 的缩放吻合)说明 **L1 GEMM 是
SM-bound**。推论:

- "把 combine 藏进 GEMM"在 SM 维度是**零和**:一个 SM 在推流就不在算
  GEMM,总功不变;唯一真正可藏的是 PCIe 线上时间(~150-250µs);
- **v1 的结构(GEMM 全速 + 全员 110 块后排空)意外地接近最优**:后排空
  阶段 reduce 与 wire 在 110 块并行下都很快(实测尾巴仅 ~183µs 且已含
  wire);
- v2 目前的结构性吃亏:24 个 comm 块在前 1/8 段干等 chunk 0,GEMM 却只有
  86 块在算 → GEMM 拖长 ~140µs,推送提前的收益抵不过。

**v2 的翻盘自由度是 v1 没有的**:v1 的 comm 块砍不得(job 就绪序需要它们
守着,第十一轮 sweep 已证伪减 SM);而 v2 的列扫聚合信号不依赖任何常驻
守望者——**把 TK_COMM_SMS_L1 压到极小(2~8),让 GEMM 拿走几乎全部 SM,
chunk 0~6 的推送由少量块喂线,尾部靠全员转岗排空**。粗账:cs_l1=4 时
GEMM ≈ 542(vs 86 块的 668),若排空受控在 ~100-150µs,L1_fused 可到
~650-690,追平或反超 v1;若 wire 在少块下喂不满,数据会直接显示。

  GEMM/暴露的此消彼长;

## 4. 裁决树(拿到数据后)

- 若 cs_l1∈{2,4} 使 v2 < 691(v1):v2 定档小预算,更新默认,报数;
- 若小预算下暴露不降反升且 08c 显示排空尾变长:wire 喂不满,
  下一刀 = 延迟选举(每 8 job 一次 wait,消 per-job wait)或 GRP=32;
- 若各档都追不平 v1:接受"US 零和"结论,L1 回滚 v1 为默认(保留 v2 代码
  与文档作为负结果沉淀),主攻方向转 sched(233)与 L0 暴露(202)。
