# L1 批次分段(TK_L1_SEG):在 TP 内部化解 combine 就绪塌缩

> 2026-07-28。docs/15 把 uniform 劣化钉死在"combine 就绪塌缩"(L1 exposure
> +2409µs @T=4096),并断言"TP 内部无解——`f⁸` 是结构性的,改顺序无用"。
> 本文推翻这个"无解":`f⁸` 论证隐含了一个前提——**GEMM 行块推进序与 token
> 无关**。打破这个前提只需要调度表已有的自由度,布局甚至一个字节都不用动。

## 1. 洞察:`f⁸` 的隐含前提

docs/15 §3.2 的论证:处理了 `f` 比例的 expert 后,一个 token 的 8 个 expert
全部落在其中的概率是 `f⁸`,所以"任何等齐 TopK 才能 combine 的设计"都必然把
combine 挤到尾部,**与顺序无关**。

这只对"行块顺序与 token 无关"的调度成立。若把 token 切成 `nseg` 批、让 GEMM
按"段"推进(段 k = **所有** expert 的第 k 批行块),则段 k 算完时批次 ≤k 的
job **确定性地**全部就绪——就绪曲线从 `f⁸` 塌缩变成 nseg 级阶梯,预归约的
1.07GB 读与 100MB 跨卡 push 摊回 GEMM 全程。

## 2. 机制:布局零改动

三个事实叠出一个几乎免费的实现:

1. **批次函数取 `batch(j) = j·nseg/S`**(j = src_dev·T+src_tok)是 j 的单调
   函数,而 canonical 布局里 expert 内行序本来就是 (src_dev, src_tok, kpos)
   = **j 升序** → 行天然按批次排好。**tp_slots / padded / slack / pull_order
   / push_order / blk_expert / slot_job / slot_w 与 canonical 逐位相同**
   (preflight 机器化断言)。零新增 padding,L0 完全不受影响。
2. **L1 的 GEMM gate 是 `no_gate`**,act 在 kernel 启动前已全部就绪(L0 与
   act 量化先完成)→ L1 行块访问序**完全自由**,重排零输入依赖。
3. dispenser 的行块 id 由 producer 单点计算再经 task_desc 广播 → 加一层
   `row_perm` 查表只改 producer 3 行,gate/信号/epilogue/store 全部零改动。

真正动的只有两张"顺序表":

- **`row_perm (nblk,)`**:段号(b) = 块首行 job 的批次(每块首行必为真实行),
  按 (段号, 块 id) 排序。段内同 expert 的行块保持相邻 → B tile 的 L2 复用
  只按段稀释,不是完全打散。
- **`job_order`**:键从 max slot 换成"8 个 slot 行块在 perm 序中的最大位置"
  (+j tie-break)——push_job 的领取序重新对齐新的就绪序。

## 3. 实算就绪曲线(真实调度表,uniform,rank 0)

release-time 口径与 docs/15 §3 完全相同(push 50.9GB/s,8KB/远端 job;
l1_seg=0 的 1121µs 对上 docs/15 的 1125µs,模型自校验通过):

| T=4096 | 50% job 就绪于 GEMM 进度 | push 尾部暴露 |
|---|---:|---:|
| l1_seg=0(现状) | 92.2% | 1121µs |
| l1_seg=2 | 51.6% | 534µs |
| l1_seg=4 | 51.6% | 236µs |
| l1_seg=8 | 51.6% | 112µs |

T=512:l1_seg=0/2/4 → 133/48/0µs。

预归约的 1.07GB `expert_out` 读(docs/15 §4.3 认定的大头)按同一条阶梯曲线
摊平——它不进 wire 模型,收益以 `TK_L1_NOGATE` 实测差值为准(见 §5)。

## 4. 代价:只有 B 的段间重读

w2 每 rank 402MB(E×H×inter fp8)。恒等序下同 expert 行块连续,B 每 expert
从 DRAM 读一次(6.3MB « L2);分段后每段重访每个 expert 一次:

```
额外 B 读 = (nseg−1) × 402MB ≈ (nseg−1) × 310µs(@1.3TB/s 假设, 待实测)
```

这笔账落在 `L1_gemm_alone`(time_tp_stages 的参考 GEMM 跟随 fused 传同一个
row_perm,与 two_level 跟随 slack 同理)→ **exposure 仍然只量通信/就绪等待,
B 代价单独可见**,归因口径不混。

净账(T=4096 uniform,粗估):nseg=2 wire 收益 ~590µs + 读摊平,付 ~310µs;
nseg=4 wire 收益 ~890µs + 读摊平,付 ~930µs。**最优 nseg 大概率在 2~4,由
上机 sweep 定**;若 GEMM 非纯带宽受限,B 重读可能被部分吸收,账会更好。

## 5. 与 NOGATE 探针的裁决关系

`TK_L1_NOGATE`(docs/15 §5.1)= 就绪塌缩总代价 = **本方案收益的硬上界**
(NOGATE ≈ nseg→∞ 且 B 零代价的理想)。裁决链:

- NOGATE 差值大(~2000µs 量级)→ 塌缩主导,本方案的阶梯化直接对症;
- NOGATE 差值小(几百 µs)→ 瓶颈是 1.07GB 读量本身;本方案仍有效(它把读
  摊进 GEMM 与计算并发),但收益封顶在 NOGATE 差值,应同时考虑
  `expert_out` 降精度(fp8,读量减半);
- 任何情况下 `TK_L1_SEG` 的 A/B 收益不应超过 NOGATE 差值——超过即测量有问题。

## 7. 正确性

- **强判据**:重排不改变任何一行的运算序(每行 GEMM 独立、K 维累加序不变、
  预归约按 kpos 顺序、final reduce 按 rank 顺序)→ **`TK_L1_SEG` on/off 的
  e2e rel_err 必须逐位一致**(0.042817506939172745)。不一致即 bug。
- preflight 四条不变量(已过,2026-07-28 本机):① row_perm 双射;② 除
  job_order/row_perm 外所有表与 canonical **逐位相同**;③ 段号沿 perm 非降;
  ④ 就绪包含——批次 b 的 job 的全部 8 个行块都在段 ≤b 的 perm 前缀内。
- host golden ↔ torch GPU 版逐元素对拍扩到 l1_seg ∈ {2,4} 档;数据流仿真按
  row_perm 序消费行块(l1_seg=4 档),对 naive 参考 rel_err < 1e-5。

## 8. 死锁审计(红线,逐条)

**无新增、无修改等待点。**

| 等待点 | 分段后的变化 | 有界性 |
|---|---|---|
| dispenser producer 领任务 | 只多一次 `row_perm[rb]` 全局读,无等待 | n/a |
| L1 GEMM gate | `no_gate`(本来就不等) | n/a |
| 行块信号(signal_epilogue → barrier row 0/1) | row_perm 是双射(preflight ①)→ 每行块仍被发放**恰好一次**,每信号的生产者/计数与恒等序完全一致,只有产生时刻的顺序变 | 生产者在同 kernel,trap 连带 |
| push_job 等 8 个 slot 行块信号(`wait_slot`) | job_order 与新就绪序对齐(等待更短);即使完全乱序也只慢不死——所有行块必然完成 | `PCIE_SPIN_GUARD`(~32s trap) |
| 跨卡:combine push / watermark / final reduce | 零改动 | 既有 guard |
| 跨 rank 依赖链 | 不变:`final ← watermark ← push ← 行块信号 ← GEMM ← act(已就绪)`,无环 | — |

L0 kernel 不接收 row_perm(nullptr),行为逐指令不变。

## 10. 未做与风险

- **tpsched 融合 sched kernel 只支持 canonical**:`TK_L1_SEG≥2` 自动回退
  torch 版(sched +~120µs)。**A/B 裁决看 time_tp_stages 分阶段数字,不看
  e2e**;定案后再给 tpsched 补 row_perm/job_order 两段(与 local_first 的
  Phase 2 同批)。
- **与 `TK_LOCAL_FIRST` 互斥**(setup assert):两者都动调度自由度,未联调。
  原理上可叠(local_first 动布局、l1_seg 动 L1 发放序),定案后再合。
- **蛇形段序**(段间 expert 方向交替,省段边界一个 expert 的 B 重读)未做:
  收益 ~6MB/段,不值增加对拍复杂度。
- **L0 侧塌缩(+238µs @T=4096)不在本方案内**:L0 行块序与 AG 流水耦合
  (gate 等 scatter),且量级小一个数量级;若 NOGATE-L0 探针日后证明值得,
  同一 row_perm 机制可复用,但 pull_order 要联动改键。
- comm 块在段边界会集中收到一批就绪 job(阶梯释放),`TK_COMM_SMS_L1`
  的拐点可能移动——sweep 时与 nseg 联合扫。
