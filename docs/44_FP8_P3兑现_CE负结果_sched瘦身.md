## 2. CE 通信:负结果定案(与 docs/35 成对的平台结论)

| 档 | e2e | vs SM 版 1756 |
|---|---:|---:|
| L0 CE | 1992 | +236 |
| L1 CE | 2206 | +450 |
| 双 CE | 2365 | +609 |
| CE 拐点 sweep 4/8/12/16 | 4861/3251/2714/2472 | 全程劣于 SM 版 |

归因:CE 版把 token 粒度的消费序流水**退化成分片粒度大块搬运**——kernel
等整个 2.1MB 分片落地才放行(cudaMemcpy peer 单流 PCIe 带宽也有限),
恰违反 docs/02 §3 粒度纪律的反向教训。挽救(分片切 chunk 多流)复杂度
暴涨而上限只有让渡税 ~200µs。**定案:本机 PCIe 上 SM 驱动+消费序细粒度
流水 > CE 大块搬运;通信引擎选择同样服从粒度纪律**。代码留档
(TK_L0_CE/TK_L1_CE 默认 0)。附带产出:持久 kernel 饿死辅助 kernel 的
死锁坑类(已入踩坑索引)+ ce:: 编排骨架(未来源端 pack 后可复用)。
