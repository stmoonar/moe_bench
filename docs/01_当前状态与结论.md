# 当前状态与结论

## 1. 当前目标与默认口径

当前主线是 RTX PRO 5000（SM120）PCIe 四卡上的 TP MoE 通算融合实现 `tktp`，与 vLLM
串行通信、计算实现对比。唯一默认测试配置是
[`configs/tp_rtx_pro5000_4gpu_fp8.yaml`](../configs/tp_rtx_pro5000_4gpu_fp8.yaml)：

| 项 | 默认值 |
|---|---|
| 模型形状 | hidden=4096，intermediate=3072，E=64，TopK=8 |
| 并行 | TP，world size=4 |
| 精度 | FP8，token 1×128 group，weight 128×128 block |
| 负载 | 512 token/rank，四卡共 2048，balanced routing |
| 计时 | warmup=20，bench=50 |
| 正确性 | 默认开启 |

测试必须从 `/workspace` 运行 `python -m moe_bench...`，并显式传主配置。专用脚本若不能直接
读取 YAML，必须逐项对齐并只记录最小覆盖。完整约束见 [05_测试与调试指南.md](05_测试与调试指南.md)。

> **路由口径（2026-07-27 起）**：新工作的**判决档是不均匀路由**（`--dist uniform` /
> `skewed`），balanced 只作完美对齐的上界参照。真实业务不会让每个 expert 都拿到整除
> ROW_BLOCK 的 token 数，而 balanced 的完美对齐会系统性地掩盖（也可能夸大）padding
> 粒度相关的效应——docs/09 的不均衡劣化 +370µs、docs/14 的分段代价都是例子。主配置
> YAML 的默认值仍是 balanced（保持历史数字可比），**不均匀档用命令行 `--dist` 覆盖**，
> 正式报数按 docs/09 §5 走 balanced + uniform 双口径。

## 2. 已经收敛的实现

- L0：源 token FP8 group 量化、FP8 AllGather 数据面（源端 posted-write push + 收端按
  消费序本地 scatter）、persistent dispenser grouped GEMM、FP32 accumulator 上的
  SwiGLU epilogue。
- L1：激活 FP8 group 量化、FP8 W2 grouped GEMM、本地 top-k 预归约、SM 驱动的细粒度
  ReduceScatter push、水位信号和最终本地归约。
- 调度：GPU builder 计入 `run()`；key 已从 int64 安全瘦身为 int32；host/GPU builder 有
  逐元素裁决。
- 协议：跨卡完成检测使用“本地原子选举唯一写者 + `st.release.sys` 定值信号 + 本地
  acquire 自旋”，不依赖远端原子 RMW。
- 工程：`tools/run_tp_all.sh` 当前每一步各自起一次独立的四进程/NCCL 生命周期
  （早期曾有跨 case 复用同一进程组的批量回归工具，已随 slim 分支移除）；每步独立
  setup/close 并保留 JSON 输出，单步超时或失败不影响其余步骤。

实现入口与数据流见 [02_实现架构.md](02_实现架构.md)。

## 3. 性能状态

**当前主配置正式回归（2026-07-26，`tp_test_results/tp_run_20260726_114848`，
PASS=12 FAIL=0，卡组 0-3，warmup=20/bench=50，serial 为 triton 兜底 config 未调优）**：

| 口径 | T=512 | T=1024 |
|---|---:|---:|
| tktp FP8 | **1508.1µs**（med 1503.2） | **2768.9µs**（med 2765.0） |
| vLLM serial FP8 | 2099.6µs（med 2085.7） | 4044.7µs（med 4043.4） |
| 相对 serial 的耗时降低 | **28.2%** | **31.5%** |

同轮阶段归因（`time_tp_stages 64 20 512`）：sched 229.0 + tok_copy 43.3 +
L0_fused 760.2 + L1_fused 538.0 + final_red 32.9；L0 exposure 93.9，L1 exposure
178.4。正确性：单卡 FP8 GEMM 裁决 L0/L1 rel_err 均 1.68e-03 OK；全链路 rel_err
tktp 4.28e-2（W1 二次量化）、serial 1.67e-2（2/2097152 元素超差）均超 3.5e-2 旧容差，

## 4. 尚未闭环

1. **baseline 未调优**：serial 一直跑 vLLM 兜底 tile config（本机无 `E=64,N=768` 条目），
   `tools/tune_triton_moe.py` 写好但尚未上机产出 JSON。调优后 serial 会变快，§3 的
   28.2%/31.5% 领先幅度需按调优后 baseline 重报（接回方式
   `VLLM_TUNED_CONFIG_FOLDER`，口径见 docs/08 §6）。
2. FP8 正确性口径仍需裁决：tktp rel_err 约 `4.28e-2`（W1"反量化→交织→重量化"二次
   量化），serial 也有 `1.67e-2`（2/2097152 元素超差）——3.5e-2 元素级容差对 FP8
   全链路本就偏紧。可选方案是将 FP8 容差校准到 `5e-2`，或从数据层直接生成交织后的
   W1 量化布局消除二次量化。未裁决前不能把性能结果称为完整正确性闭环。
3. 优化线剩余空间（2026-07-26 盘后账）：NCCL all_gather 捕获进 graph（sched 内
   ~20-40µs）；L1 的 act 量化下沉 L0 epilogue（~35-50µs，牵动主循环重标定）；final_red
   内 watermark straggler。L0 GEMM 引擎侧差距（重标定 76.9µs/70%）账在 docs/11。
