## 2. 定案:L1 N 维分解在本平台是负结果,v1 回默认

三轮完整证据链(docs/32→35):

1. 协议正确(48/48 全绿,列扫聚合/选举/watermark 成立);
2. 粒度病修复后(GRP=16,1294→786)仍慢 v1 ~95µs;
3. 换序无罪(cm-rm delta +12µs)→ 慢在推送调度结构;
4. 小预算(v2 独有自由度)单调反向 → 无参数空间可翻盘。

**根因(平台差异,与 Comet 的 NVLink 结论相反)**:本机 L1 GEMM 是
SM-bound,通算重叠在 SM 维度是零和——一个 SM 在归约/推流就不在算 GEMM,
总功不变;唯一可藏的是 PCIe 线上时间,而 **v1 的"GEMM 全速跑完 + 全员
110 块并行后排空"已经把线上时间藏在了高并行排空里**(实测尾巴仅 ~180µs,
含 wire)。v2 把归约/推送挪进 GEMM 窗口,只是把同样的 SM 功挪了位置,
还多付 chunk 门控与细粒度推送的调度费。

**Comet 的 N 维分解在 NVLink 上成立的前提**:通信由 copy engine/专用
路径承担(不占 SM),重叠是真增量;PCIe + SM 驱动推送的平台上该前提
不成立。此结论对 sm120/PCIe 移植是一手平台事实,归档。
