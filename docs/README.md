## 信息优先级

发生冲突时按以下顺序处理：

1. `AGENTS.md` 的协作和测试硬约束；
2. `configs/tp_rtx_pro5000_4gpu_fp8.yaml` 的正式默认口径；
3. `HANDOFF.md` 顶部的最新进展和待办；
4. 本目录的收敛文档；
5. `归档/` 中按时间形成的历史记录。

归档中的 `docs/NN`、`docs/01~18` 等写法是历史原路径，均指同一归档目录中的对应编号文件。
历史结果使用过不同卡组、warmup、分支和临时覆盖，引用数字时必须同时核对原文与 run manifest，
不能覆盖当前主配置口径。

> **平台事实不是跨机器常量。** 归档中的带宽、RTT、最佳 `comm_sms` 和性能负结果主要来自
> 早期 16 卡服务器及其卡组；当前协作环境是 8 卡机器。即使 GPU 型号相同，PCIe switch、
> NUMA、ACS/IOMMU、BIOS、driver、时钟和卡组位置也会改变结论。换机器或换拓扑后按
> [04_平台边界与负结果.md](04_平台边界与负结果.md#1-事实的三个层级) 重新定标。

## 后续维护规则

- 当前事实和最终裁决更新到对应主题文档，不再为每一轮新增一个顶层 `docs/NN_*.md`。

- 负结果不删除：先把结论写入 [04_平台边界与负结果.md](04_平台边界与负结果.md)，原始证据留在归档。
