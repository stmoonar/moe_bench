# TP 性能矩阵单进程复用

## 问题

原 `tools/run_tp_all.sh` 把每个性能 case 都作为独立的
`python -m moe_bench.tools.run_tktp` 命令执行。每条命令都会重新启动四个
worker、初始化 NCCL、导入 vLLM、生成并量化权重，实际几十次 kernel 计时只占
不到一秒，绝大部分墙钟时间消耗在重复初始化。

## 实现

- `distributed.run_distributed_suite`：一次 `mp.spawn` 和 process group 生命周期内
  顺序执行多个 case；每个 case 仍重新 `scheme.setup/run/close`。
- 相同 shape、精度和 seed 的本地权重按 rank 缓存，serial/TK 以及同精度 A/B
  共享权重，不重复生成和 FP8 量化。
- `tools/run_tp_bench_suite.py`：必须显式读取
  `configs/tp_rtx_pro5000_4gpu_fp8.yaml` 作为主配置，仅从 run manifest 读取
  precision、token、iters 和 `TK_*` 最小覆盖项；23 个核心性能 case 保持原 JSON
  文件名。
- `tools/run_tp_all.sh` 默认 `REUSE_BENCH=1`，把 23 个核心性能 case 合为
  `04_bench_suite_reuse`。设置 `REUSE_BENCH=0` 可恢复逐 case 进程隔离；使用
  `STEPS`/`FOCUS` 时自动回退，避免破坏原步骤过滤语义。
- runner 的默认 Python 和卡组同步当前 8 卡环境：
  `/root/miniconda3/envs/vllm-td/bin/python`，卡组优先 `0,1,2,3`、其次
  `4,5,6,7`；自动挑卡会校验 GPU index 确实存在。

## 隔离边界

正确性、schedule 裁决和分阶段归因仍独立运行。原因是 TK 常驻 kernel 死锁时，
复用 suite 只能整体超时退出；逐 case 模式仍是定位 barrier/IPC/CE 死锁的可靠回退。
suite 内每个 case 都恢复环境变量、销毁 scheme、强制 GC 并清 CUDA cache，避免 A/B
状态串案。

## 本地校验

- Python 语法编译通过。
- 基于主配置和 manifest 的 dry plan 校验为 23 个 case，输出路径无重复。
- 验证 `TK_COMM_SMS` sweep 会同步覆盖 `TK_COMM_SMS_L1`，CE/default 环境不会串案。
- Windows 本机没有 vLLM/CUDA，未执行 GPU 端到端测试；上机首次应先跑
  `QUICK=1`，失败时用 `REUSE_BENCH=0` 对照。
